# ESP32 传感器监控系统 — 设计文档

## 1. 项目概述

基于 ESP32 开发板采集环境数据（温度、湿度、土壤湿度、光照强度），在 Windows PC 上通过桌面程序实时显示与分析的监控系统。

**核心约束：** 项目要求使用 C 语言风格编写（Windows API 实现系统调用），仅图形界面层保留 SFML C++ 库。

**通信方式：** 服务端 TCP

### 2.2 C 语言风格设计决策

项目选择纯 C 风格而非 C++ 的原因：

| 特性 | C 风格实现 | 替代的 C++ 方案 |
|------|-----------|----------------|
| 字符串 | `char[]` 定长数组 + `strncpy`/`snprintf` | `std::string` |
| 动态数组 | 环形缓冲区（定长数组 + head/tail） | `std::vector`/`std::deque` |
| 互斥锁 | `CRITICAL_SECTION` + 手动 Enter/Leave | `std::mutex` + `std::lock_guard` |
| 线程 | `CreateThread` + `WaitForSingleObject` | `std::thread` |
| 条件变量 | `CONDITION_VARIABLE` + `SleepConditionVariableCS` | `std::condition_variable` |
| 原子操作 | `volatile LONG` + `InterlockedExchange` | `std::atomic<bool>` |
| 回调 | 函数指针 + `void* context` | `std::function` + lambda |
| 文件操作 | `FILE*` + `fprintf`/`fopen` | `std::ofstream` |
| 时间操作 | `time()` / `GetTickCount64()` | `std::chrono` |
| 字符串格式化 | `snprintf` | `std::ostringstream` |
| 控制台输出 | `printf` / `fprintf` | `std::cout` / `std::cerr` |
| 睡眠 | `Sleep()` | `std::this_thread::sleep_for` |

### 2.3 模块划分

| 模块 | 职责 | 对外接口 |
|------|------|---------|
| **system** | 主入口、线程管理、数据采集循环 | 无（程序入口） |
| **sensor_data** | 传感器数据定义 | `SensorData` 纯数据结构（C 兼容） |
| **number_parser** | 字符串 → 数值数组 | `extractNumbers(const char*, double*, int)` |
| **data_source** | 数据源模式的实现 | `dataThreadFunc` / `runServerMode` / `runMqttMode` |
| **analysis_rules** | 趋势检测、PAR 计算、阈值判断 | `AnalysisRules_init/feedDataPoint/checkUrgent/clearAlarm` |
| **server_client** | TCP 服务端日志查询与指令发送 | `ServerClient_init/connect/disconnect/fetchLogs` |
| **sensor_display** | SFML 图形界面（保留 C++） | `SensorDisplay` 类 |
| **build.bat** | 构建脚本 | 批处理编译链接 |

## 3. 并发模型

### 3.1 线程概览

| 线程 | 数量 | 职责 | 同步方式 |
|------|------|------|---------|
| 主线程 | 1 | SFML 事件循环 + 渲染 + 手动指令发送 | — |
| 数据线程 | 1 | 三种模式之一的数据采集与分析 | `SensorDisplay` 互斥接口 |
| 错误处理线程 | 1 | 消费错误数据队列 | `CRITICAL_SECTION` + `CONDITION_VARIABLE` |

### 3.2 线程安全策略

```
共享数据              保护方式
─────────────────────────────────────
g_errorQueue          CRITICAL_SECTION g_errorMutex
g_display             仅主线程写数据线程读 → SensorDisplay 内部锁
g_rules               runXxxMode 内栈分配，子线程通过全局指针读

SensorDisplay 内部：
  m_data/m_history    m_mutex
  m_analysisData      m_analysisMutex
  s_cmdQueue          s_cmdMutex
```

数据线程直接启动服务端模式：

```
dataThread启动
    │
    └── runServerMode() ──── 循环 60s 轮询服务端日志
         └── 失败 → 程序退出
```

## 4. 数据流设计

### 4.1 传感器数据流

```
服务端推送 "25.3 55.1 42.0 813"
    │
    ▼
tryParseSensorData → SensorData
    │
    ├─→ processData() → printf + SFML updateData()
    │
    └─→ (每 5 分钟) runAnalysisPoint()
           ├─ feedDataPoint() → 环形缓冲区
           ├─ checkUrgent() → 趋势/PAR/阈值 → 指令
           ├─ sendCmdRaw(TCP) → 服务端
           └─ setAnalysisData() → SFML
```

### 4.2 指令流

```
手动按钮点击（主线程）
    │ SensorDisplay::pushCommand(cmd)
    ▼
    ┌── UI 线程直接处理 → sendCmdRaw(TCP) → 服务端
    │   (服务端模式下，UI 线程带发送)
    │
    └── 数据线程 → processManualCommands()
            ├── sendCmdRaw(TCP) → 服务端
            └── logMessage("[手动] 指令 X → 标签")

自动分析（数据线程）→ runAnalysisPoint()
    ├── checkUrgent() 返回指令数组
    └── 同手动指令发送流程
```

## 5. 环形缓冲区设计

用于替代 `std::deque` 存储传感器历史数据。

```c
typedef struct {
    double data[RING_MAX];  // RING_MAX = 500
    int head;               // 读取指针
    int tail;               // 写入指针
    int count;              // 当前元素数
} RingBuffer;
```

操作：
- `ringPush()`：尾端追加，满则覆盖头部
- `ringAt(idx)`：相对头部的索引访问（支持遍历）
- `ringAvg()`：全缓冲区求平均（用于温度平均计算）

设计理由：固定大小 = 无动态内存分配，满足实时系统要求。500 个数据点以 5 分钟粒度可存储约 41 小时历史。

## 8. 数据格式协议

### 8.1 ESP32 → PC （串口）

每行 4 个空格分隔的浮点数：

```
<温度> <湿度> <土壤湿度> <光照强度>
25.3 55.1 42.7 813
```

### 8.2 PC → ESP32 （串口指令）

单字符指令：

| 指令 | 动作 |
|------|------|
| `1` | 开补光 |
| `3` | 蜂鸣器报警 |
| `4` | 开灌溉 |
| `5` | 关补光 |
| `6` | 关灌溉 |
| `8` | 清除报警 |
| `9` | 关闭所有执行器 |

### 8.3 PC ↔ 服务端 （TCP）

| 方向 | 格式 | 说明 |
|------|------|------|
| PC→服务端 | `CONNECT\n` | 建立连接 |
| PC→服务端 | `PING\n` | 心跳 |
| PC→服务端 | `GET_LOGS begin=<ISO> end=<ISO>\n` | 查询日志 |
| PC→服务端 | `CMD:<指令>\n` | 发送控制指令 |
| 服务端→PC | `CONNECTED\n` | 确认连接 |
| 服务端→PC | `PONG\n` | 心跳回复 |
| 服务端→PC | `DATA:<数值行>\n` | 实时数据推送 |
| 服务端→PC | `ALERT:<行>\n` | 异常数据推送 |
| 服务端→PC | `LOGS_BEGIN\n...日志行...\nLOGS_END\n` | 日志查询响应 |

### 8.4 PC ↔ 服务端（实时推送）

| 数据类型 | 方向 | 载荷 | 说明 |
|------|------|------|------|
| `esp32/data` | 服务端推送 | `25.3 55.1 42.0 813` | 传感器数据 |
| `esp32/alert` | 服务端→PC | `!25.3 55.1 42.0 813` | 异常数据 |

## 9. 分析规则设计

### 9.1 趋势检测算法

```
输入：最近 N 个温度数据点
过程：
  mid = N / 2
  avgFirst  = avg(data[0..mid])
  avgSecond = avg(data[mid..N])
  返回 (avgSecond - avgFirst) > TREND_DELTA (0.5°C)

连续 TREND_COUNT (3) 次检测到趋势 → 触发报警 '3'
```

### 9.2 PAR 计算

```
PPFD (μmol/m²/s) = 光照强度 (lux) × 转换系数 (0.0185)
DLI  (mol/m²)    = avgPPFD × 小时数 × 3600 / 1e6

转换系数为占位值，需在实际环境中标定。
```

### 9.3 温度互锁

温度报警激活时禁止灌溉：

```
if temperature > TEMP_MAX (35°C) → tempAlarmActive = true
if tempAlarmActive → canRunPump = false（即使土壤湿度低）
if temperature < TEMP_RELEASE (30°C) + 收到 '8' 指令 → 清除报警
```

### 9.4 用水量累计

```
用水量 (L) = 水泵流量 (L/min) × (灌溉结束时间 - 灌溉开始时间) / 60
流量默认值 2.0 L/min（占位，需按实际水泵修改）
```
