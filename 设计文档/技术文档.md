# ESP32 传感器监控系统 — 技术文档

## 1. 项目概述

从 ESP32 开发板读取环境温度、湿度、土壤湿度、光照强度四个传感器数据，通过 **SFML** 图形界面提供实时仪表盘、历史趋势分析与手动控制的桌面监控程序。

**主要特性：**
- 实时仪表盘：3 个柱状仪表 + 折线趋势图（温度、土壤湿度、光照）
- 数据分析页：3 图表横排 + 最小/最大/平均统计
- 智能建议页：基于传感器数据的操作建议
- 手动控制页：4 个指令按钮 + PAR/用水量/报警面板
- 串口/演示双模式：未接开发板自动使用模拟数据
- 多线程架构：主线程渲染 UI，独立线程采集数据，错误处理线程
- 数据日志：带时间戳的文本日志文件（5分钟间隔 + 异常立即写入）

## 3. 模块详解

### 3.1 `sensor_data.hpp` — 传感器数据结构

```cpp
struct SensorData
{
    double temperature = 0.0;    // 环境温度 (°C)
    double humidity = 0.0;       // 环境湿度 (%)
    double soilMoisture = 0.0;   // 土壤湿度 (%)
    double lightIntensity = 0.0; // 光照强度 (lux)
};
```

**用途：** 在采集线程和 UI 线程之间传递一帧传感器数值。

---

### 3.2 `serial_reader.hpp/.cpp` — 串口读写

封装 Windows 串口 API（`CreateFile` / `ReadFile` / `WriteFile`）。

| 函数 | 说明 | 调用方式 |
|------|------|----------|
| `bool open(portName, baudRate)` | 打开串口 | `reader.open("COM6", 115200)` |
| `void close()` | 关闭串口 | `reader.close()` |
| `HANDLE nativeHandle()` | 获取句柄 | 传给 SerialDispatcher |
| `bool readLine(string &out)` | 读一行 | `reader.readLine(line)` |
| `bool writeText(text, outError)` | 发送文本 | `reader.writeText("1", err)` |

**串口参数：** COM6, 115200 baud, 8-N-1, 无超时（立即返回）。

**关键细节：**
- 打开串口后禁用 DTR/RTS，防止 ESP32 因 DTR 电平变化而复位
- 调用 `PurgeComm` 清空收发缓冲区，去除上次残留的脏数据

### 3.3 `serial_dispatcher.hpp/.cpp` — 串口分发

在后台线程持续读取串口，根据当前状态分发数据：

| 函数 | 说明 |
|------|------|
| `void start(handle, onError)` | 启动后台读取线程 |
| `void stop()` | 停止线程并等待退出 |
| `void expectResponse()` | 标记下一行是正常响应 |
| `void clearExpectResponse()` | 取消标记（writeText 失败时回滚） |
| `string waitResponse(timeoutMs)` | 等待正常响应，超时返回空串，默认 3000ms |

**分发逻辑：**
- `m_expectingResponse == true` → 放入主队列，主线程消费
- `m_expectingResponse == false` → 调用 errorCallback（推入 `g_errorQueue`）

**调用顺序（防止竞态）：**
```cpp
dispatcher.expectResponse();       // 先标记（防 ESP32 响应太快被误路由）
reader.writeText("0", writeErr);   // 再发触发指令
string line = dispatcher.waitResponse(3000);  // 等待响应（3 秒超时）
```

### 3.6 `data_logger.hpp/.cpp` — 数据日志

```cpp
class DataLogger {
public:
    // 打开文件（追加模式）
```

**日志写入规则：**

| 数据类型 | 写入条件 | 格式 |
|----------|----------|------|
| 正常数据 | 距上次写入 ≥ 5分钟 | `温度: 25.3℃  湿度: 55.1%  土壤: 42.7%  光照: 813lux` |
| 异常数据 | 立即写入 | `[异常] 温度: 38.5℃  湿度: 60.0%  土壤: 42.0%  光照: 800lux` |

### 3.7 `analysis_rules.hpp/.cpp` — 规则分析

```cpp
class AnalysisRules {
public:
    // 每 5 分钟：存入一个数据点（供趋势 + PAR 累计）
    void feedDataPoint(const SensorData &data);

    // 每 5 分钟：趋势检测 + PAR 控制 + 阈值判断，返回指令
    std::vector<char> checkUrgent();

    // 收到 '8' 时清除温度报警（仅关蜂鸣器）
    void clearAlarm();

    // 配置读写（线程安全）
    void updateConfig(const AnalysisConfig &cfg);
    AnalysisConfig getConfig() const;

    // 状态查询（供 UI 显示）
    double totalWaterUsed() const;  // 累计用水量 (L)
    bool   tempAlarmActive() const; // 温度报警是否激活
    double avgPpfd() const;         // 全程平均 PPFD
    double currentDli() const;      // 当前累计 DLI
    double avgTemperature() const;  // 全程平均温度
    bool   isIrrigating() const;    // 是否正在灌溉
    bool   isTrendAlarm() const;    // 趋势报警是否激活
};
```

**阈值表（在 `analysis_rules.cpp` 中配置）：**

| 条件 | 动作 | 指令 |
|------|------|------|
| 土壤湿度 < 30% 且 无温度报警 | 开启灌溉 | `'4'` |
| 土壤湿度 > 65% 且 正在灌溉 | 关闭灌溉 + 计算用水量 | `'6'` |
| 温度 > 35°C | 蜂鸣器 + 禁止灌溉 | `'3'` |
| 温度持续上升（趋势） | 蜂鸣器 | `'3'` |
| PAR 不足 (<5 μmol/m²/s) | 开补光 | `'1'` |
| PAR 充足 (>15 μmol/m²/s) | 关补光 | `'5'` |
| 手动清除报警 | 仅关蜂鸣器 | `'8'` |
| 关闭所有 | 全部关闭 | `'9'` |

**用水量计算（占位数据，需按实际修改）：**
```
水泵流量: 2.0 L/min
用水量 = 流量 × (停止时间 - 开始时间) / 60
```

#### `main()` 流程

```
1. SetConsoleOutputCP(CP_UTF8)           ← 控制台 UTF-8
2. CreateDirectoryA("temp")               ← 日志目录
3. SensorDisplay display                  ← 创建 SFML 窗口
4. reader.open("COM6", 115200)            ← 打开串口
5. thread dataThread(runRealMode/Demo)    ← 启动数据线程
6. while (display.isOpen() && g_running)  ← SFML 主循环
     display.processEvents()
     display.render()
     sleep(16ms)  // ~60fps
7. g_running = false                      ← 通知退出
   dataThread.join()
   reader.close()
```

#### `runRealMode()` 采集循环

```
AnalysisRules rules;              ← 循环外持久（趋势/用水量状态保持）

while (g_running) {
    1. dispatcher.expectResponse()          ← 先标记（防竞态）
    2. writeText("0")                       ← 发触发指令
       → 失败 → clearExpectResponse() 回滚
    3. line = dispatcher.waitResponse(3000) ← 等 3 秒
       → 空串 → timeoutCount++
    4. tryParseSensorData(line) → SensorData
    5. processData(data)                    ← 输出 + UI（不写日志）

    6. 5分钟分析点:
       if (距上次 ≥ 5分钟)
         → runAnalysisPoint(data, &reader)
            ├─ feedDataPoint(data)       ← 存入历史
            ├─ checkUrgent()              ← 趋势 + PAR + 阈值 + 互锁
            ├─ writeText(cmd) → ESP32    ← 发指令
            ├─ applyCommand(cmd)          ← 同步执行器状态到 UI
            ├─ log() → sensor_log.txt    ← 写日志
            ├─ setAnalysisData() → UI    ← 推送分析数据
            └─ 输出摘要到控制台

    7. 条件休眠:
       if (显示窗口打开)   sleep(1s)
       else                sleep(5min)

    8. processManualCommands(&reader)      ← 检查手动指令队列
       → '8' → rules.clearAlarm()
       → 其他 → writeText(cmd)
}
```

#### `runDemoMode()` 模拟循环

```
AnalysisRules rules;

while (g_running) {
    1. SimulatedSensor::generate() → SensorData  ← 模拟数据
    2. processData(data)           ← 输出 + UI

    3. 5分钟分析点:                 ← 同 runRealMode，reader=nullptr
       runAnalysisPoint(data, nullptr)
       ├─ feedDataPoint / checkUrgent
       ├─ logMessage(cmd)           ← 仅打日志（无串口）
       └─ log() / setAnalysisData()

    4. 每 5 次推送一条模拟异常       ← 测试错误处理线程
    5. 条件休眠 (1s 或 5min)
    6. processManualCommands(nullptr)
}
```

## 5. 数据流

### 5.1 数据格式

ESP32 每行通过串口发送 4 个空格分隔的数字：

```
25.3 55.1 42.7 813
↑     ↑    ↑    ↑
温度  湿度 土壤  光照(lux)
```

注意：PC 端分析逻辑中"湿度"指土壤湿度，空气湿度不参与控制判断。光照单位统一为 lux。

### 5.2 数据流向

```
ESP32/SimulatedSensor
    │
    ▼
tryParseSensorData() → SensorData
    │
    ├─→ processData()
    │      ├─→ std::cout（控制台）
    │      └─→ SensorDisplay::updateData()（SFML 仪表盘）
    │
    ├─→ 5分钟槽位判断（距上次写入 ≥ 5min？）
    │      ├─→ 是 → DataLogger::log()（temp/sensor_log.txt）
    │      └─→ 否 → 跳过本次写入
    │
    ├─→ 异常数据 → DataLogger::logAnomaly()（立即写入，带 [异常] 标记）
    │
    └─→ readLatestFromLog()
           └─→ AnalysisRules::observe()
                  ├─→ 正常 → prevAnomaly 取消标记
                  └─→ 异常 → writeText(cmd) → ESP32 执行器
```

### 5.3 错误数据流

```
ESP32 自发上报 → SerialDispatcher readerLoop
    │ m_expectingResponse == false
    ├─→ errorCallback(line)
    │      └─→ g_errorQueue.push(line)
    │             └─→ errorHandlerThread
    │                    ├─→ tryParseSensorData → 显示 + DataLogger::logAnomaly()
    │                    └─→ logMessage("[异常上报] " + line)
```

## 8. 常见问题

**Q: 启动后没反应，没有数据输出？**
A: 可能是 Windows 打开串口时 DTR 拉高导致 ESP32 复位。程序已自动禁用 DTR (`DTR_CONTROL_DISABLE`) 并清空缓存 (`PurgeComm`)。如仍异常，检查 ESP32 的 DTR 硬件连线或手动按一下开发板 RST 键。

**Q: 串口打不开？**
A: 检查是否已插入 ESP32，设备管理器中确认 COM6 是否存在。程序会自动降级为演示模式。

**Q: SFML 中文显示乱码？**
A: 确保字体加载成功。程序启动时控制台会输出 `[显示] 字体 XXX`。使用 `L"中文"` 宽字符串 + 编译标志 `-finput-charset=UTF-8 -fexec-charset=UTF-8`，字体路径为 `msyh.ttc`。

**Q: 日志文件在哪？写入频率？**
A: `temp/sensor_log.txt`（相对于工作目录）。规则：
- 正常数据：每 5 分钟写入一条
- 异常数据：立即写入，行首带 `[异常]` 标记
格式：
```
[2026-05-13 10:30:25.123]  温度: 25.3℃  湿度: 55.1%  土壤: 42.7%  光照: 813lux
[2026-05-13 10:35:00.456]  温度: 25.8℃  湿度: 54.2%  土壤: 43.1%  光照: 792lux
[2026-05-13 10:36:23.789]  [异常] 温度: 38.5℃  湿度: 60.0%  土壤: 42.0%  光照: 800lux
```

**Q: 为什么有时数据会卡住几秒？**
A: `waitResponse()` 有 3 秒超时机制。如果 ESP32 连续超时，控制台会输出 `[警告] 串口无响应，已连续超时 N 次`。这通常是物理连接问题，程序会自动重试。

**Q: 数据能收到但有时会漏掉一些帧？**
A: 旧版本存在竞态条件：`writeText("0")` 之后才调用 `expectResponse()`，ESP32 响应太快时会被误路由到错误回调。已修复为先 `expectResponse()` 再 `writeText()`。
