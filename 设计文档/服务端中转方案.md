# ESP32 数据服务端中转方案

## 背景

当前数据流：

```
ESP32 ──USB串口(COM6)──→ PC 端分析程序
```

改造目标：

```
ESP32 ──WiFi──→ 服务器 ──网络──→ PC 端分析程序
```

去掉 USB 物理连线，支持远程监控。

---

## 整体架构

```
┌──────────┐    WiFi     ┌───────────┐    TCP/IP    ┌──────────┐
│  ESP32   │ ──────────→ │  服务器   │ ←────────── │  PC 端   │
│ (传感器)  │ ←────────── │  (中转)   │ ──────────→ │ (分析UI)  │
│  (执行器) │   MQTT     │           │   MQTT      │          │
└──────────┘            └───────────┘            └──────────┘
```

核心通信协议：**MQTT**（轻量级物联网消息协议）

### 为什么选 MQTT

| 特性 | MQTT | HTTP REST | WebSocket |
|------|------|-----------|-----------|
| 双向通信 | ✅ 发布/订阅 | ❌ 轮询 | ✅ 全双工 |
| 带宽占用 | 低（2字节头） | 高（HTTP头） | 中 |
| ESP32 库支持 | ✅ PubSubClient | ✅ HTTPClient | ⚠ 支持有限 |
| 断线重连 | ✅ 内置 | ❌ 需自实现 | ⚠ 需自实现 |
| 实时性 | ✅ 即时推送 | ❌ 轮询延迟 | ✅ 即时 |
| 复杂度 | 低 | 中 | 高 |

## 数据流设计

### 上报方向（ESP32 → 服务器 → PC）

```
ESP32 传感器数据
    │
    ├─ 定时采集（当前保持每 1 秒或根据 PC 指令）
    │
    ├─ 发布到 MQTT 主题: esp32/data
    │     └─ 格式: "25.3 55.1 42.0 813"
    │        （与当前串口格式一致，PC 端解析逻辑不变）
    │
    └─ 服务器保存到本地日志（可选持久化）
          │
          └─ PC 端订阅 esp32/data，收到后走现有 processData() 流程
```

### 下发方向（PC → 服务器 → ESP32）

```
PC 端需要发送指令（'1'/'3'/'4'/'8'/'9' 等）
    │
    ├─ 发布到 MQTT 主题: esp32/cmd
    │     └─ 格式: "1" / "3" / "9" 等
    │
    └─ ESP32 订阅 esp32/cmd，收到后在 loop() 中执行
          │
          └─ 执行器动作（与当前 switch/case 一致）
```

### 自发上报（ESP32 检测到异常 → 服务器 → PC）

```
ESP32 检测到数据超限
    │
    ├─ 发布到 MQTT 主题: esp32/alert
    │     └─ 格式: "!25.3 55.1 42.0 813"（与当前 "!" 前缀格式一致）
    │
    └─ PC 端订阅 esp32/alert，收到后走现有 errorHandler 流程
```

---

## MQTT 主题设计

| 主题 | 方向 | QOS | 说明 |
|------|------|-----|------|
| `esp32/data` | ESP32 → PC | 0 | 正常传感器数据 |
| `esp32/alert` | ESP32 → PC | 1 | 异常自发上报 |
| `esp32/cmd` | PC → ESP32 | 1 | 控制指令 |
| `esp32/status` | ESP32 → PC | 1 | 连接状态（在线/离线心跳） |

## 服务器选择

### 方案 A：本地 Mosquitto（推荐起步）

```
PC 上直接运行 Mosquitto broker
ESP32 ←WiFi→ PC ←同一局域网→ Mosquitto
```

| 优点 | 缺点 |
|------|------|
| 不需要额外硬件 | ESP32 和 PC 必须在同一局域网 |
| 零成本，Windows 可装 | 无法远程访问 |
| 延迟最低 | |

### 方案 B：云服务器（如阿里云轻量服务器）

```
ESP32 ←WiFi→ 路由器 ←→ 公网云服务器 ←→ PC（可在任何网络）
```

| 优点 | 缺点 |
|------|------|
| 任何地点都可访问 | 需要云服务器（约 34元/月） |
| 支持多 PC 同时连接 | 延迟取决于网络 |
| 可做数据持久化/历史查询 | |

## 需要修改的文件

### ESP32 端

| 文件 | 改动 |
|------|------|
| `platformio.ini` | 添加 WiFi + MQTT 库依赖 |
| `esp32main.cpp` | 移除 `Serial.begin` / `Serial.read` 相关代码 |
| — | 新增 `WiFi.begin` 连接路由器 |
| — | 新增 MQTT 客户端初始化 |
| — | 数据改为 `mqtt.publish("esp32/data", line)` |
| — | 指令改为 `mqtt.subscribe("esp32/cmd")` + 回调处理 |
| — | `check_and_alert()` 改为 `mqtt.publish("esp32/alert", line)` |

### PC 端

| 文件 | 改动 |
|------|------|
| `src/serial_reader.hpp/.cpp` | 保留或改名为 `mqtt_reader.hpp/.cpp` |
| — | 用 MQTT 客户端库替换 `CreateFile` / `ReadFile` |
| — | 添加 `subscribe()` 替代 `readLine()` |
| — | `writeText()` 改为 `mqtt.publish("esp32/cmd", text)` |
| `src/system.cpp` | `SerialReader reader` → `MqttClient client` |
| — | `reader.open("COM6")` → `client.connect("broker_ip")` |

### 新增文件

| 文件 | 说明 |
|------|------|
| `src/mqtt_client.hpp/.cpp` | 封装 MQTT 发布/订阅/回调（替换 SerialReader） |

## 实施步骤

1. 搭建 MQTT Broker（方案 A 或 B）
2. ESP32 端：改 `platformio.ini` 加 MQTT 库，`esp32main.cpp` 加 WiFi + MQTT 逻辑
3. PC 端： 
   - 可选使用 [Eclipse Paho C++](https://github.com/eclipse/paho.mqtt.cpp) 库
   - 或通过 WebSocket 桥接（如果不想引入新依赖）
4. 测试连通性：ESP32 发 → Broker → PC 收
5. 逐步下线 USB 串口路径

## 当前代码的兼容性

当前 PC 端的 `SerialDispatcher` 设计（`expectResponse` / `waitResponse` / error callback）是基于**请求-响应**模式的（发 "0" → 等回复）。改为 MQTT 后需要调整为**发布-订阅**模式：

```
之前: 发 "0" → 阻塞等响应 → 处理 → 再发 "0" → ...
之后: 持续接收 esp32/data → 有数据就处理 → 需要时发 esp32/cmd
```

调整范围：
- `SerialDispatcher` 不再需要（或改造为 MQTT 订阅派发器）
- `AnalysisRules` 逻辑不变
- `SensorDisplay` 不变
- 主循环改为事件驱动（收到消息 → 处理）而非定时轮询

## 附录：云服务器搭建教程（Ubuntu 22.04 + Mosquitto）

以 Ubuntu 22.04 LTS 为例，适用于阿里云、腾讯云、华为云等主流云厂商。

### 1. 选购云服务器

| 配置项 | 推荐值 | 说明 |
|--------|--------|------|
| 系统 | Ubuntu 22.04 LTS | 长期支持版 |
| 规格 | 2核2G | 跑 Mosquitto 绰绰有余 |
| 带宽 | 3Mbps | 传感器数据量极小，够用 |
| 计费 | 按年 | 轻量服务器约 300-500元/年 |

### 2. 连接服务器

```bash
# Windows 用 PowerShell 或 CMD
ssh root@你的服务器IP

# 首次登录会提示输入密码（购买时设置的）
```

### 3. 安装 Mosquitto

```bash
# 更新软件源
apt update

# 安装 Mosquitto 服务端 + 客户端工具
apt install -y mosquitto mosquitto-clients

# 查看运行状态（默认已开机自启）
systemctl status mosquitto
```

### 4. 配置 Mosquitto

默认情况下 Mosquitto 只允许本机连接，需要放开远程访问：

```bash
# 编辑配置文件
nano /etc/mosquitto/mosquitto.conf
```

在文件末尾追加：

```
# 监听 1883 端口（MQTT 默认端口）
listener 1883 0.0.0.0

# 允许匿名连接（后续可改为密码认证）
allow_anonymous true
```

保存后重启服务：

```bash
systemctl restart mosquitto
```

### 5. 配置防火墙

**云服务器控制台安全组**：入方向放行 TCP 1883 端口。

Ubuntu 内防火墙：

```bash
ufw allow 1883/tcp
```

### 6. 本地验证

```bash
# 终端 A：订阅
mosquitto_sub -h 127.0.0.1 -t "esp32/test"

# 终端 B：发布
mosquitto_pub -h 127.0.0.1 -t "esp32/test" -m "Hello"
```

终端 A 应显示 `Hello`。

### 7. 外部验证

在本地 PC 安装 Mosquitto 客户端（[官网下载](https://mosquitto.org/download/)），然后：

```cmd
mosquitto_sub -h 8.137.48.225 -t "esp32/data"
```

另开窗口：

```cmd
mosquitto_pub -h 你的服务器IP -t "esp32/data" -m "25.3 55.1 42.0 813"
```

### 8. 密码认证（可选，推荐）

```bash
# 创建密码文件，加两个用户
mosquitto_passwd -c /etc/mosquitto/passwd esp32
mosquitto_passwd /etc/mosquitto/passwd pc_user

# 修改配置
echo "password_file /etc/mosquitto/passwd" >> /etc/mosquitto/mosquitto.conf
echo "allow_anonymous false" >> /etc/mosquitto/mosquitto.conf

systemctl restart mosquitto
```

### 9. 常用运维命令

```bash
journalctl -u mosquitto -f    # 查看实时日志
systemctl restart mosquitto   # 重启
systemctl status mosquitto    # 查看状态
```
